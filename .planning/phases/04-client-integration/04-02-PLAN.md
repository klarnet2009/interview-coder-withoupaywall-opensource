<!-- Backend processing API endpoints -->
From backend/src/processing/processing.routes.ts:
```
POST /processing/extract  → (Bearer token, { provider, imageDataList, language, model? }) → extracted problem data
POST /processing/solution → (Bearer token, { provider, promptText, model? }) → solution text
POST /processing/debug    → (Bearer token, { provider, debugPrompt, imageDataList, model? }) → debug analysis
```

From backend/src/credits/credit.routes.ts:
```
GET /credits/balance → (Bearer token) → { credits: number }
```

From backend/src/stripe/stripe.routes.ts:
```
GET  /credits/packages  → (public) → { packages: [{ id, credits, priceInCents, name }] }
POST /credits/checkout   → (Bearer token, { packageId }) → { url: string } (Stripe Checkout URL)
```

export interface ProcessingProviderStrategy {

    **Create electron/BackendProcessingProvider.ts** — Implementation of ProcessingProviderStrategy that calls the backend:
    - Implements the `ProcessingProviderStrategy` interface from `electron/processing/types.ts` per D-01.

    - `isConfigured()`: returns `true` if `authService.getAccessToken()` is not null — authenticated user can always use backend.
    - `extractProblem(request)`: POST `/processing/extract` with `{ provider, imageDataList, language, model }` using BackendClient.
      - Map `request.images` (base64 strings from screenshot queue) to `imageDataList`.
      - Map `request.language` from the language config.
      - Map `request.provider` from config `apiProvider`.
      - On 402 response: emit `out-of-credits` IPC event to renderer, return `{ success: false, error: "Insufficient credits", statusCode: 402 }`.
      - On 401 response: emit `auth-expired` IPC event (BackendClient handles refresh, but if refresh fails...).
      - On success: parse backend response to match `ProblemInfo` interface.
    - `generateSolution(request)`: POST `/processing/solution` with `{ provider, promptText, model }`.
      - Map `request.problemInfo` + language to `promptText`.
      - On 402: same credit handling as extract.
      - On success: return solution string.
    - `generateDebug(request)`: POST `/processing/debug` with `{ provider, debugPrompt, imageDataList, model }`.
      - Same pattern as extract with screenshot images.
      - On success: return debug string.
    - Error mapping: 401 → "Authentication required", 402 → "Insufficient credits", 429 → "Rate limited", 503 → "Service unavailable", network errors → "Network error".
    - Import and use `problemInfoSchema` from existing formatters if needed for response parsing.

    **Update electron/ProcessingHelper.ts** — Use BackendProcessingProvider when authenticated:
    - Add `useBackend: boolean` flag to ProcessingHelper constructor or a method to switch.
    - When `authService.isAuthenticated()` is true: use `BackendProcessingProvider` via BackendClient.
    - When NOT authenticated: fall back to direct provider (existing behavior for backward compatibility, though this path should rarely be used).
    - Actually, since this is a SaaS transformation, the app should ALWAYS use backend when authenticated. Modify `initializeProvider()`:

      - If NOT authenticated, create and use the existing `ProcessingProviderOrchestrator` (direct provider) as fallback.
    - Update `processScreenshots()` to handle 402 credit errors: if BackendProcessingProvider returns 402, send `out-of-credits` IPC event to renderer.

    - `createCheckoutSession(packageId)`: POST `/credits/checkout` with auth token and `{ packageId }`.

    **Update electron/preload.ts** — Expose credits IPC channels:
