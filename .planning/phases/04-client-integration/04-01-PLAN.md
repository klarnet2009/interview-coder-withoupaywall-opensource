<objective>
Integrate backend authentication into the Electron app so users can sign up, log in, and maintain sessions across restarts with automatic token refresh.

Purpose: The Electron app currently has no authentication — users manage their own API keys locally. This plan adds the auth layer that connects to the backend's JWT auth system, enabling the SaaS model where AI operations go through the backend.

Output: BackendClient (HTTP client), AuthService (auth state management), Login/Signup UI components, and App.tsx flow changes that check auth state instead of API key state.
</objective>

  <action>
    **Create BackendClient.ts** — HTTP client for backend API communication:
    - Use Node.js built-in `https` module (Electron main process, not browser) OR `axios` (already a dependency). Prefer axios for consistency with existing codebase.
    - Config: Read `BACKEND_URL` from ConfigHelper (default: `http://localhost:3001` for dev).
    - Methods: `get(path, accessToken?)`, `post(path, body, accessToken?)` — all return typed response objects.
    - Auto-refresh logic: If a request returns 401 with "Access token expired" error, automatically call `/auth/refresh` with stored refresh token, retry the original request once, then emit `auth-expired` IPC event if refresh also fails.
    - Store tokens in a `SecureTokenStorage` pattern: save accessToken and refreshToken to a JSON file in `{userData}/auth.json` (NOT in config.json — separate concerns). Use atomic write pattern (write temp → rename) matching ConfigHelper's approach.
    - Export singleton `backendClient` instance.

    **Create AuthService.ts** — Auth state management:
    - `login(email, password)` → POST `/auth/login` → store tokens → return user data
    - `signup(email, password)` → POST `/auth/register` → store tokens → return user data
    - `refreshTokens()` → POST `/auth/refresh` → store new tokens → return success
    - `logout()` → POST `/auth/logout` → delete stored tokens → clear state
    - `getAuthState()` → return `{ authenticated: boolean, user: { id, email } | null }` from cached state
    - `getAccessToken()` → return cached access token (used by BackendClient for authenticated requests)
    - On app startup: load tokens from `auth.json`, validate by calling GET `/auth/me`. If token expired, try refresh. If refresh fails, clear tokens and mark as unauthenticated.
    - Emit `auth-state-changed` event via EventEmitter when auth state changes.
    - Export singleton `authService` instance.

    **Update ConfigHelper.ts** — Add `BACKEND_URL` to config:
    - Add `backendUrl` to Config interface with default `http://localhost:3001`.
    - Load from `config.json` or `BACKEND_URL` env var.
    - Add `getBackendUrl(): string` method.

    **Update electron/main.ts** — Initialize auth service:
    - Import and initialize `authService` in `initializeApp()` after `initializeHelpers()`.
    - Pass `authService` to `ipcHandlers` deps.
    - On app startup: `authService.initialize()` loads tokens, validates, sets state.

    **Update electron/ipcHandlers.ts** — Add auth IPC channels:
    - `auth-login`: (email, password) → authService.login()
    - `auth-signup`: (email, password) → authService.signup()
    - `auth-refresh`: → authService.refreshTokens()
    - `auth-logout`: → authService.logout()
    - `get-auth-state`: → authService.getAuthState()
    - Add to REQUIRED_PRELOAD_INVOKE_CHANNELS array.

    **Update electron/preload.ts** — Expose auth IPC channels:
    - Add `authLogin`, `authSignup`, `authRefresh`, `authLogout`, `getAuthState` invoke calls.
    - Add `onAuthExpired` event listener.

    **Update src/types/electron.d.ts** — Add auth types:
    - Add `AuthState` interface: `{ authenticated: boolean; user: { id: string; email: string } | null }`.
    - Add `AuthResult` interface: `{ success: boolean; error?: string; user?: { id: string; email: string } }`.
    - Add auth method declarations to `ElectronAPI` interface.
