  <action>
    Per CRED-02, PAY-01, PAY-02:

    1. Install Stripe SDK:
       ```bash
       cd backend && npm install stripe
       ```

    2. Update `backend/src/config.ts` — add Stripe configuration to the Zod schema:
       - `STRIPE_SECRET_KEY: z.string().min(1, 'STRIPE_SECRET_KEY is required')` — required for v1 (not optional; production needs it)
       - `STRIPE_WEBHOOK_SECRET: z.string().min(1, 'STRIPE_WEBHOOK_SECRET is required')`
       - `STRIPE_SUCCESS_URL: z.string().default('https://interviewcoder.app/credits/success')`
       - `STRIPE_CANCEL_URL: z.string().default('https://interviewcoder.app/credits/cancel')`
       - `CREDIT_PACKAGES: z.string().default('50:500,150:1200,500:4000')` — format is "credits:price_in_cents" comma-separated
       Also update Config interface and `backend/.env.example`.

    3. Create `backend/src/stripe/stripe.service.ts`:
       - Import Stripe from 'stripe' and create instance with `config.STRIPE_SECRET_KEY`
       - Define `CREDIT_PACKAGES` parsed from config — each package is `{ id: string, credits: number, priceInCents: number, name: string }`
         - Package IDs: "credits_50", "credits_150", "credits_500"
         - Parse the CREDIT_PACKAGES config string into structured objects
       - `createCheckoutSession(userId: string, packageId: string): Promise<StripeResult<{ url: string }>>`:
         a. Validate packageId against available packages — return 400 if invalid
         b. Create Stripe Checkout session with:
            - `mode: 'payment'`
            - `line_items` with the selected credit package as a price_data item
            - `success_url` from config
            - `cancel_url` from config
            - `metadata: { userId, packageId }` — links payment to user
         c. Return `{ success: true, data: { url: session.url } }`
       - `handleWebhookEvent(payload: string | Buffer, sig: string): Promise<StripeResult<{ received: boolean }>>`:
         a. Verify webhook signature using `stripe.webhooks.constructEvent(payload, sig, config.STRIPE_WEBHOOK_SECRET)` — rejects tampered payloads per security
         b. Switch on `event.type`:
            - `checkout.session.completed`: Extract userId and packageId from session.metadata, look up the package, call `creditService.addCredits(userId, package.credits, 'purchase', 'Credit purchase: {packageId}')`
            - Any other event type: Log and return success (no action needed)
         c. Return `{ success: true, data: { received: true } }`
         d. On signature verification failure: return `{ success: false, error: 'Invalid signature', statusCode: 400 }`
       - Use discriminated union `StripeResult<T>` matching the established pattern
       - Export singleton `stripeService`

    4. Write tests first (TDD RED), then implement (TDD GREEN):
       - `backend/src/stripe/stripe.service.test.ts`
       - Mock Stripe SDK using vi.mock for unit tests
       - Mock creditService.addCredits for webhook processing tests
       - Test: valid packageId creates session
       - Test: invalid packageId returns 400
       - Test: checkout.session.completed adds credits
       - Test: other event types are no-ops
       - Test: invalid signature returns error

    5. Verify TypeScript compiles with `npx tsc --noEmit`.
